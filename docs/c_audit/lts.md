# LTS (letter-to-sound) — C vs. Python audit

Reference C tree: `${DECTALK_SRC}/src/dapi/src/lts/` plus the bundled
US dictionary at `src/dapi/src/dic/Dic_us_2002.txt` (the live source
the `say` binary loads).

Reference Python: `src/dectalk/lts/` (the rule code) and
`src/dectalk/dic/` (the lexicon loader), plumbed through
`dectalk.api.speak.text_to_dectalk_phonemes`.

This audit lists structural and behavioural deltas between the two
LTS pipelines. Each section is laid out as **C source** /
**Python current** / **Delta**, ranked by how often the gap surfaces
in everyday speech. The headline finding: **on a 20-word sample of
common English vocabulary the Python LTS path diverges from the C
oracle in 8/20 cases (40 %)**, dropping to 0/200 on the curated
phoneme-parity corpus precisely because the corpus is hand-built to
the words and contexts the Python path already handles.

The curated corpus has masked an LTS layer that is roughly an order
of magnitude smaller than its C counterpart (236 vs. ~4 800 lines of
rule code; ~15 k vs. ~14 k dictionary entries — see §1) and is
missing the form-class disambiguation, suffix engine, and prefix /
compound rule set that produce most of the divergences below.

## Method

1. Built the C oracle via `scripts/agent_oracle_env.sh` +
   `scripts/setup_c_oracle.sh` (issue #89 branch
   `claude/audit-lts-issue89`).
2. Compared `dectalk.text_to_dectalk_phonemes(text)` against
   `CAPI.convert_to_phonemes(text)` byte-for-byte on:
   - all 200 randomly-sampled prompts from `tests/parity/_corpus.py`
     (the 133 k-entry parity corpus) — **0 divergences**;
   - 20 single common English words (`breakfast`, `sandwich`,
     `rainbow`, `beautiful`, `technology`, `company`, …) —
     **8 divergences (40 %)**;
   - 69 hand-picked vocabulary probes spanning loanwords, silent
     letters, irregular vowels, and stress alternations —
     **30 divergences (43 %)**;
   - 10 noun/verb minimal-pair sentences (`I record` vs `a record`,
     `the object` vs `I object`, …) — **15/20 utterances
     diverge** (Python collapses to a single form per spelling).

Every numerical claim below cites the exact C source line range or
the Dic_us_2002 entry it came from.

## 1. Layer sizes

**C source.** US-locale LTS rule code is split across six files
under `src/dapi/src/lts/`:

| File | Lines | Role |
|---|---:|---|
| `l_us_con.c` | 1 256 | Letter-class tables, consonant tables |
| `l_us_pr1.c` | 1 238 | Process / sign / number / punctuation pre-rules |
| `l_us_ru1.c` |   894 | Main rule engine (`ls_rule_show_phone` etc.) |
| `l_us_suf.c` |   655 | Suffix engine |
| `l_us_ad1.c` |   547 | Adjacency rewrites |
| `l_us_ma1.c` |   120 | Misc helpers |
| `l_us_cha.c` |    93 | Character classification |
| **Total** | **~4 803** | |

Plus `Dic_us_2002.txt` (13 989 lines / ~13 700 entries; the live
dictionary at runtime) and `udic_us` for user-installed entries.

**Python current.** `src/dectalk/lts/` ships 60 modules totalling
~9 800 lines, but the active letter-to-sound rules collapse into
`rules_us.py` (236 lines, 81 hand-written rules). The remaining
modules are either placeholder scaffolding, lookup tables, or
infrastructure that is not yet wired into
`text_to_dectalk_phonemes`. The bundled lexicon is
`src/dectalk/data/lexicon_us_full.txt` (15 059 lines / ~14 800
entries) generated by `scripts/build_full_lexicon.py` from
`Dic_us.txt` — note: the build script consumes `Dic_us.txt`, but
the `say` binary actually serves from `Dic_us_2002.txt`. They differ
substantially (see §3).

**Delta.** The rule layer is ~20× thinner than the C original.
Most of the C rule engine (the suffix and adjacency stages, the
context-sensitive rewrites for `ough/igh/eigh`, the
prefix-detection logic in `l_us_pr1.c`) has no Python counterpart.
The Python `rules_us.py` is a flat ordered list of grapheme →
phoneme mappings with regex-style left/right context; the C engine
is multi-pass and pattern-driven.

## 2. Dictionary lookup vs form-class disambiguation

**C source.** Dic_us_2002 entries are tagged with a form-class
letter (`P` for primary, `S` for secondary, `N` for noun-only,
plus a 29-bit feature mask). Stress-shifted noun/verb minimal
pairs occupy two entries:

```
record,P,r'EkRd,...   # primary form (noun) -> r-EK-rd
record,S,r|k'ord,...  # secondary form (verb) -> ri-KORD
present,P,priz'Ent,...  # verb -> pri-ZENT  (note: also gets ) marker)
present,S,pr'Ezxnt,...  # noun -> PRE-zent
object,P,'abJEkt,...   # noun -> OB-ject
object,S,xbJ'Ekt,...   # verb -> ob-JECT
desert,P,d'EzRt,...    # noun -> DE-zert
desert,S,d|z'Rt,...    # verb -> di-ZERT
```

`dic_comm.c` selects between them based on neighbouring tokens
(determiners → primary; auxiliary / first-position → secondary)
and a part-of-speech table.

**Python current.** `dectalk.dic.lookup` returns a single phoneme
list per spelling. `scripts/build_full_lexicon.py` collapses the
two C entries down to one (the first / longest), and the form-class
letter is dropped. The bundled US-full lexicon line
`RECORD R AH0 K OW1 R D` is the **verb** stress pattern; the noun
pattern is unrecoverable from the bundled data.

**Delta.** Every noun/verb stress-shift minimal pair speaks in
Python with one stress regardless of context. Probed 10 pairs;
15/20 utterances diverge. Examples (C → Py):

| Context | C output | Python output |
|---|---|---|
| `a record`     | `r ' ehk rrd`         | `r axk ' owr d`    |
| `I record`     | `r ixk ' owr d`        | `r axk ' owr d`    |
| `the object`   | `' aab jhehk t`       | `axb jh' ehk t`     |
| `I object`     | `axb jh' ehk t`       | `axb jh' ehk t`     |
| `a present`    | `p r ' ehz axn t`     | `p r ' ehz ixn t`   |
| `I present`    | `) p r iyz ' ehn t`   | `p r ' ehz ixn t`   |
| `an increase`  | `' ihn k r iys`       | `' ihnxk r iys`     |
| `I increase`   | `) ihn k r ' iys`     | `' ihnxk r iys`     |
| `the desert`   | `d ' ehz rrt`         | `d axz ' rrt`       |
| `I desert`     | `d ixz ' rrt`         | `d axz ' rrt`       |

This is by far the largest single source of LTS divergence on
natural English text. Fix requires preserving the `P`/`S` tag in
the bundled lexicon and adding a form-class disambiguator (the
`dic.form_class_bits` module already exists as a placeholder).

## 3. Bundled lexicon is mis-sourced

**C source.** Runtime dictionary is `Dic_us_2002.txt` (13 989
lines).

**Python current.** `lexicon_us_full.txt` is generated from
`Dic_us.txt` (15 537 lines, the 1996/1997 baseline). The version
header in `lexicon_us_full.txt` confirms this:

```
# Generated by scripts/build_full_lexicon.py
# Source: /tmp/dectalk-source/src/dapi/src/dic/Dic_us.txt
```

Comparing the two files shows several thousand entries either
revised or absent in the older Dic_us.txt. The 2002 file also
adds the form-class minimal pairs documented above (`record`,
`present`, etc., which are *not* in `Dic_us.txt`).

**Delta.** Single-source change: `build_full_lexicon.py` should
read `Dic_us_2002.txt` instead. This is a one-line fix in the
build script but needs careful handling of the new form-class
column (see §2 — keeping P vs S as separate entries).

## 4. Words missing from the Python lexicon

**C source.** Dic_us_2002 entries shipped for: `borough`, `gnome`,
`psychology`, `pneumonia`, `museum`, `university`, `incredible`,
`hospital`, `engineer`, `breakfast`, `salad`, `database`,
`pipeline`, `kubernetes`, `docker`, `rendezvous`, `bough`, `dough`,
`plough`, etc.

**Python current.** Many of these are absent from
`lexicon_us_full.txt` so they fall through to the `rules_us.lts()`
hand-written ruleset. Probed 13 common words; 7 returned `None`
from `lookup()` (`BOROUGH`, `GNOME`, `PSYCHOLOGY`, `PNEUMONIA`,
`UNIVERSITY`, `MUSEUM`, `INCREDIBLE`).

**Delta.** The bundled lexicon is missing words present in the
upstream source. Two root causes: (a) lower-case keying in the C
source vs upper-case keying in the Python build (entries like
`'em` and `'n` survive; multi-word entries like `1 1/4` may be
dropping); (b) `build_full_lexicon.py`'s line filter is dropping
entries it shouldn't. Needs a row-count diff between the two
files to confirm.

## 5. `rules_us.py` rule gaps

**C source** (`l_us_con.c` + `l_us_ru1.c`). The C rule engine has
multi-letter clusters with full left/right context, plus a
**prefix-detection pre-pass** (`l_us_pr1.c` lines 200-450) that
strips morphological prefixes (`anti`, `un`, `non`, `mis`, `re`,
`pre`, `dis`, `inter`) before applying base-word rules, plus a
**suffix back-pass** that handles `-tion`, `-sion`, `-ity`, `-ous`,
`-ic`, `-al`, `-ly`, `-ed`, `-ing`, `-er`, `-est`, `-y`, `-ize`,
`-ise`, `-ism`, `-ist`, `-ment`, `-able`, `-ible`, `-ive`,
`-ence`, `-ance`, `-ent`, `-ant`, etc.

**Python current** (`rules_us.py` lines 47-143). 81 hand-written
rules. The vowel rules cover only the 4-letter clusters
`EAU/EAR/AIR/OUR/EER/OOR/OUGH/AUGH/EIGH/IGH` plus the 16 standard
digraphs and a single VCe magic-E pattern. No prefix detection.
No suffix engine. No syllable-aware stress placement (just
"primary on first vowel").

**Delta.** Five concrete rule gaps from the probe set:

1. **`GN-` initial** → C silent G (`gnome -> n owm`), Python
   pronounces both letters (`g n owm`). Same for `psy-` (`p s -`
   vs C silent P → `s ay-`), `pn-`, `mn-`, `pt-`. The C uses an
   initial-cluster table; Python's rule list has no such entry.

2. **`-OUGH` final without T** → C gives `aw` for `bough/dough/
   plough` and `ow` for `borough/thorough` (positional / lexical),
   Python rule 0xF (`_Rule("OUGH", "", "", ("AH", "F"))`) always
   emits `AH F` (`rough/tough/enough` behaviour) for words
   without a following T. Five out of five `-ough` words probed
   diverge.

3. **`-TURE` / `-TUR-`** → C palatalises t → ch
   (`architecture -> ' aar k ixt ehk chrr`, Python emits literal
   `t yur` → `' aar chiht ehk t yur`). The C suffix table handles
   this; Python `rules_us.py` has no `T → CH / _ U` rule.

4. **`-CIAN` / `-CIAL` / `-TION` palatalisation** → C
   palatalises `c/t` to `sh` before `ian/ial/ion`
   (`electrician -> ehllixk t r ' ihshixn`), Python emits literal
   `s + ihaen` (`' ehllehk t r ihs ihaen`).

5. **Stress placement on derivational suffixes.** C applies the
   "stress shifts one syllable left of a Latinate suffix" rule
   (`-tion`, `-ity`, `-ic`, `-ical`, `-ify`, `-igy`,
   `electricity -> ehllixk t r ' ihs ixt iy` — primary on the
   penult). Python's `_add_stress` puts primary on the first vowel
   unconditionally, so `electricity` reads as `' ehllehk t r ihs
   iht iy`.

## 6. Schwa quality (`IX` vs `AH`)

**C source.** `l_us_ad1.c` reduces unstressed `IH/EH/AE` to the
**high schwa `IX`** when next to certain consonants
(`hospital -> hx' aos p ixt el`), while preserving the **mid
schwa `AH`** elsewhere. The choice is governed by an adjacency
table.

**Python current.** `dectalk.dic.dectalk_phonemes` maps both `x`
and `X` to ARPABET `AH`. There is no `IX` in the Python ARPABET
inventory, and the schwa-quality alternation is lost.

**Delta.** Pervasive but small: nearly every multisyllabic word
shows at least one `IX → AH` swap. Examples:

- `hospital`: C `hx' aos p ixt el` vs Py `hx' aos p axt el`
- `foreign`: C `f ' owr axn` vs Py `f ' owr ixn` (Python overshoots:
  emits `ix` where C wants `ax`)
- `lieutenant`: C `lluwt ' ehn ixn t` vs Py `lluwt ' ehn axn t`
- `civilization`: C `s ixv ihllixz ' eyshixn` vs
  Py `s ' ihv ihllihz aeshixn`

Audibly this is a smaller divergence than the form-class issue,
but it touches almost every prompt that exercises a multisyllabic
common noun.

## 7. Compound-marker injection (`*` and `)` markers)

**C source.** `l_us_pr1.c` injects the compound-marker `*` between
the components of a closed compound (`pipeline -> p ' ayp * ll`
ayn`, `breakfast -> b r ' ehk * f ixs t`, `database -> d ' eyt ax*
b eys`). The compound boundary is detected from morphological
analysis (rooted in `l_us_suf.c` / `l_us_ad1.c`). The `)`
phrase-start marker is emitted by the form-class disambiguation
pass when a verb form is selected (`I present -> ) p r iyz ' ehn
t`).

**Python current.** No compound detection. Tokenises on
whitespace / punctuation only. The `text_to_dectalk_phonemes`
helper hard-codes a 30-entry curated `vpstart_words` set
(`SELL/SELLS/SELLING/SEE/SEES/...`) to fake the `)` marker on a
small list of high-frequency verbs.

**Delta.**

- `breakfast/pipeline/database`: missing `*` (1 of 1 across all
  probed compound nouns).
- `)` marker present on 30 hard-coded words; absent on every
  other verb the C path tags with it. Probes that diverge include
  `present` (verb form), `conduct` (verb), `permit` (verb),
  `increase/decrease/export` (verb).

## 8. Headline numeric summary

| Probe set | Size | Diverge | Rate |
|---|---:|---:|---:|
| Random sample from `tests/parity/_corpus.py` | 200 | 0 | 0 % |
| 20 common English vocabulary words | 20 | 8 | 40 % |
| 69 hand-picked vocabulary probes (loanwords / silents / irregulars) | 69 | 30 | 43 % |
| 10 noun/verb sentence pairs (20 utterances) | 20 | 15 | 75 % |
| 29 suffix / derivation probes (`walked/walking/walker`, …) | 29 | 18 | 62 % |

The 0 % rate on the curated corpus is a **selection-bias artefact**:
`tests/parity/_corpus.py` was grown by the parity-port team
specifically to cover what the Python LTS handles. The audit
above runs the same comparison on out-of-corpus vocabulary and
recovers the underlying ~40-75 % divergence rate.

## 9. Recommended porting order

Priorities driven by audibility × frequency of the divergence
class on natural English text:

1. **Re-source the bundled lexicon from `Dic_us_2002.txt`** and
   preserve the form-class column (§3 + §2). Single-script change
   under `scripts/build_full_lexicon.py` plus a schema change in
   `dectalk.dic.lookup`. Closes ~75 % of the noun/verb-pair
   divergences.

2. **Port the C form-class disambiguator** (`dic_comm.c`'s
   determiner/auxiliary scan). Wire it into
   `text_to_dectalk_phonemes` between tokenisation and lookup. The
   placeholder modules `dectalk.dic.form_class_bits` and
   `dectalk.lts.first_verb_lookup` are the obvious landing spots.

3. **Port the suffix engine** (`l_us_suf.c`, ~655 lines). Most
   audible gain: `-tion / -ity / -ic / -ical / -ician`
   palatalisation + stress shift (§5.3-5.5). Will close most
   suffix / derivation divergences.

4. **Initial-cluster table for silent letters** (`gn-`, `pn-`,
   `ps-`, `mn-`, `pt-`, `wr-`, `kn-`). Small (~30 entries).
   `rules_us.py` patch.

5. **Compound `*` marker injection** (§7). Requires the same
   morphological analysis the suffix engine provides; deferrable
   until step 3 is done.

6. **`IX` schwa quality** (§6). Pervasive but audibly small.
   Defer until phoneme-set unification is on the table.

## 10. Out-of-scope (not LTS proper)

- Rate-command (`[:rate 250]`) sample-count drift — that's a
  PH/timing issue, see `docs/c_audit/prosody.md` §durations.
- Punctuation marker mapping (period/comma/exclaim) — already
  byte-identical between Python and C.
- ARPABET → DECtalk encoder — verified byte-identical on the
  corpus by `tests/parity/test_python_phonemes_vs_c_parity.py`
  (the divergences this audit catches surface *before* the
  encoder, in the word-lookup stage).
