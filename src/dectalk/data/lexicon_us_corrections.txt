# Python front end must match for inflected corpus forms, e.g. BLESS ->

# stress) and #281 (full-corpus sweep), preserved across the #332

# no longer corrections); what remains is the set the source omits.
#

#   uv run python scripts/build_full_lexicon.py \

# SEVEN: Dic_us.txt spells it s'Ev|n (|=IX), which the C runtime speaks
# for the bare word (`s ' ehv ixn`). But the multi-digit number pipeline
# routes the digit-7 word through the lexicon, and there the runtime says
# `s ' ehv axn` (AX) — the reading '1234567890' needs. One lexicon entry
# can't hold both context-dependent readings; the number reading is the
# corpus-tested one (the bare word is not), so AX wins here (binary-wins;
# same reading the pre-#332 lexicon carried). Costs the bare-word dict
# probe only. ELEVEN keeps its IX reading — its corpus uses are all the
# bare word, no digit-11 number appears.
SEVEN S EH1 V AX0 N
